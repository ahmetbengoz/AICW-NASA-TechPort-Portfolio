# Supplementary material

## Learning outcome-conditioned criterion importance for technology portfolio screening

This supplement reports the audit details, complete secondary results and implementation checks supporting the blinded main manuscript. It contains no author-identifying information.

## S1 Data audit and sample flow

The frozen TechPort snapshot contains 299 project records. The legacy modelling variables have 214 complete cases, but 13 of these projects are not recorded as completed. The revised primary sample therefore contains 201 completed projects. Five completed projects have zero planned TRL gain and are excluded from the target-normalised attainment outcome, leaving 196 projects. The generated files `analysis_sample_primary.csv` and `analysis_sample_secondary.csv` preserve the included project identifiers and all constructed variables.

Taxonomy rarity is calculated once on the frozen 299-project snapshot as the reciprocal frequency of the primary taxonomy code. This portfolio-level construction is then joined to the analytical samples. It is not recalculated within validation folds because it is treated as a descriptive property of the frozen choice universe, not an outcome-estimated parameter.

## S2 Repeated cross-validation design

The outer design uses five repetitions of shuffled five-fold cross-validation with seed 20260811. Splits are generated once per outcome and reused for all learners. Elastic Net performs its penalty and mixing-parameter selection through five-fold cross-validation confined to each outer training set. Random Forest and Extra Trees each use 200 trees, minimum leaf size two and all predictors as candidate split variables. Histogram gradient boosting uses learning rate 0.05, 150 iterations, at most 15 leaf nodes and L2 regularisation 0.1.

For each outer test fold, every feature is permuted ten times. The increase in test MAE is the raw importance. Negative raw values are retained in the detailed CSV output, counted in the clipping-frequency diagnostic, clipped to zero and normalised. If all clipped values are zero, an equal vector would be substituted and flagged; the run manifest records any such event.

The five repeat-level results are paired because every learner receives identical partitions. Wilcoxon signed-rank tests use the learner with the lowest primary mean MAE as the descriptive reference, and Holm adjustment is applied across the nine comparisons. With five pairs, the smallest attainable two-sided p-value is coarse. No adjusted comparison is significant, so the analysis does not declare a single winning learner.

## S5 Generalisation diagnostics

Programme-grouped validation uses five repetitions of group-balanced five-fold splitting, with programme title as the group. Each repetition assembles one out-of-group prediction for every project. The chronological diagnostic trains on the earliest 80% of projects by recorded start date and tests on the latest 20%. Hyperparameter tuning for Elastic Net remains inside the training data. These tests are stricter diagnostics, not evidence that all snapshot fields were historically frozen.

## S6 MCDM comparison profiles

Standard-deviation weights and MEREC are calculated from the ratio-normalised primary decision matrix. The FUCOM comparison is solved from the disclosed synthetic order and adjacent priority ratios. It does not represent elicitation from NASA or any other stakeholder. The cross-learner median takes the median of the four mean proxy weights and renormalises the result.

## S7 Ranking and robustness diagnostics

Learner-specific weights are propagated through the corrected WASPAS and MARCOS equations. The full project-level ranks and scores for every outcome, profile and method are in `rankings.csv`. Agreement tables retain Spearman correlation, Kendall tau and top-10 overlap.

For Monte Carlo perturbation, each primary median weight is multiplied by an independent uniform draw on [0.8, 1.2] and the vector is renormalised. Five thousand draws are generated from the fixed study seed. `rank_acceptability.csv` reports project-level best rank, median rank, worst rank and probability of entering the top ten. The high local stability should be interpreted jointly with the low outcome-to-outcome agreement.

## S8 Reproducibility verification

The complete analysis is generated by `python scripts/run_analysis.py`. The run manifest records the seed, software versions, sample sizes, model settings and SHA-256 hash of every generated analytical output. The notebook invokes the same script rather than maintaining a second implementation. The continuous-integration workflow creates a clean environment, runs the analysis and checks the expected files.

All reader-facing results in the main manuscript and supplement are drawn from generated CSV files. The legacy v1 results remain recoverable from repository history and the first Zenodo version but are intentionally excluded from the current results folder because they used a different sample and flawed or incompletely documented procedures.
